=== DEMO ANTES: flujo registro/búsqueda/actualización sobre RepositorioPaciente ===
Mismo dato de entrada, mismo código cliente, distintas subclases sustituidas.

--- Repositorio bajo prueba: RepositorioPaciente (tipo base) ---
[OK]    registrar() -> id=1
[OK]    buscarPorDocumento("no existe") -> null (correcto)
[OK]    actualizar() -> (boolean) true

--- Repositorio bajo prueba: RepositorioPacienteExtranjero (subclase) ---
[ROTO]  registrar() lanzó InvalidArgumentException: El pasaporte es obligatorio para pacientes extranjeros.
        -> El cliente esperaba el mismo comportamiento del tipo base.
        -> Se continúa la demo con id=0 para exhibir también las fallas siguientes.
[OK]    buscarPorDocumento("no existe") -> null (correcto)
Actualizado OK
[ROTO]  actualizar() lanzó TypeError: Antes\RepositorioPacienteExtranjero::actualizar(): Return value must be of type bool, null returned
        -> El tipo base garantiza que actualizar() siempre retorna bool.

--- Repositorio bajo prueba: RepositorioPacienteMenorEdad (subclase) ---
[OK]    registrar() -> id=1
[ROTO]  buscarPorDocumento() lanzó RuntimeException: No se encontró paciente menor de edad con documento GT-NO-EXISTE (falta tutor).
        -> El tipo base nunca lanza excepción por 'no encontrado'.
[OK]    actualizar() -> (boolean) true

=== CONCLUSIÓN DE LA DEMO ===
El repositorio base funciona en los tres pasos. Las subclases sustituidas
rompen el flujo (excepción inesperada en registrar/buscarPorDocumento, o
TypeError en actualizar). Esto es una violación empírica del Principio de
Sustitución de Liskov: sustituir el tipo base por la subclase SÍ altera la
corrección del programa cliente.
